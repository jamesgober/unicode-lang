# unicode-lang v1.0.1 — Hardening

**A patch from the LexerSketch audit.** v1.0.1 removes a quadratic path in normalization that a hostile identifier could reach, makes CI run the full official conformance suite instead of silently skipping it, and adds ASCII fast paths to every entry point. The public API is unchanged, and normalization output is byte-identical: the full `NormalizationTest.txt` suite passes unchanged, and the old ordering algorithm is kept in the tests as a reference the new one must match.

## What is unicode-lang?

The Unicode text primitives a language front end needs — identifier rules (UAX #31), display width (UAX #11), and all four normalization forms (UAX #15) — from compact tables generated directly from the Unicode Character Database (16.0.0). No third-party dependencies, `no_std` (identifiers and width need no allocator), and fully safe (`#![forbid(unsafe_code)]`).

## Breaking changes

**None.** The frozen 1.0 surface is untouched, and every function returns exactly what it returned in 1.0.0: each fast path is tested against the table lookup it replaces at every code point, and the new canonical ordering is tested against the old one.

## Security

- **Quadratic normalization (H11).** Canonical ordering — putting combining marks in order of their combining class — was an insertion sort over the decomposed text. A long run of marks whose classes alternate (U+0301 is class 230, U+0323 is class 220) made it `O(n²)`. Combining marks are `XID_Continue`, so a lexer that accepts Unicode identifiers accepts such a string as an identifier, and normalizing it (as UAX #31 recommends) stalled: one letter plus 256 000 marks took 57 s in a release build, and a million marks about ten minutes. Each maximal run of non-starters is now scanned once; a run already in order (the usual case) is left alone, and an out-of-order run is sorted once with the standard library's stable sort over `(class, scalar)` pairs. Normalization is now `O(n log n)`: the million-mark input takes 24 ms. Both algorithms are stable sorts by class within the same runs, so the output is identical; the unit tests keep the insertion sort and compare against it on every sequence of up to four scalars from a pool of starters and marks (with equal classes, so stability shows), on property-generated input, and on a 2 000-mark alternating run.
- **Conformance never ran in CI (M67).** `tests/conformance.rs` returned early when `dev/ucd/NormalizationTest.txt` was missing, and that file is gitignored, so CI passed without running the 19 965-record suite. Now:
  - `dev/fetch_ucd.sh` downloads pinned Unicode 16.0.0 files from unicode.org and checks each against the SHA-256 recorded in `dev/ucd.sha256`; a mismatch deletes the download and fails.
  - The CI workflow runs it for `NormalizationTest.txt` on every platform and sets `UNICODE_LANG_REQUIRE_UCD=1`, which turns a missing file into a test failure.
  - Without the variable, a local run with no data passes and prints a skip notice that the test harness does not capture, naming the command that fetches the data.
  - The test checks that the file's header names the release in `UNICODE_VERSION`, and that it holds more than 19 000 records, so a truncated or wrong file cannot pass.

## Changed

- **ASCII fast paths (M68, patch part).**
  - `is_xid_start`, `is_xid_continue`, and `char_width` answer ASCII without a table lookup.
  - `is_xid` and `str_width` check pure-ASCII strings a byte at a time, with no UTF-8 decoding.
  - `normalize` and `is_normalized` recognise pure-ASCII input with `str::is_ascii` and return at once: `is_normalized` allocates nothing, and `normalize` allocates only the `String` its frozen signature returns.
  - Inside mixed text, ASCII scalars skip the quick-check, decomposition, and composition lookups.
  - Each shortcut is tested against the table at every code point from U+0000 to U+10FFFF; for decomposition and composition, tests assert that no table entry involves an ASCII scalar, which is what makes the shortcut exact.
- Test and bench targets build without default features: the normalization tests are gated on `alloc`, and the bench requires it.
- `dev/gen_tables.rs` documents the actual regeneration steps. With the pinned data it reproduces `src/tables.rs` byte for byte (checked for this release).

## Fixed

- The crate-level doctest called `normalize` unconditionally, so `cargo test --no-default-features` failed in 1.0.0.

## Performance

Criterion means, Windows x86_64, Rust stable, release build. Before and after were measured back to back on the same machine under the same background load; that machine was busy, so absolute numbers run higher than the 1.0.0 table, and the ratio is the meaningful column.

| Operation                                          | 1.0.0     | 1.0.1     | Change   |
|----------------------------------------------------|----------:|----------:|---------:|
| `is_xid_start` (ASCII)                             |   6.09 ns |   0.81 ns |    7.5×  |
| `is_xid_continue` (ASCII)                          |   6.32 ns |   0.86 ns |    7.4×  |
| `is_xid` (16-byte ASCII identifier)                |   95.8 ns |   12.2 ns |    7.9×  |
| `is_xid` (`Δpressure_2`)                           |   68.7 ns |   16.9 ns |    4.1×  |
| `char_width` (ASCII)                               |   8.98 ns |   0.45 ns |     20×  |
| `str_width` (4 KiB ASCII)                          |   38.1 µs |   1.26 µs |     30×  |
| `str_width` (mixed 48-column string)               |    498 ns |    135 ns |    3.7×  |
| `normalize` (4 KiB ASCII → NFC)                    |   1.34 µs |    103 ns |     13×  |
| `normalize` (4 KiB ASCII + one decomposed letter)  |    101 µs |   17.6 µs |    5.7×  |
| `normalize` (mixed scripts → NFD)                  |   1.02 µs |    537 ns |    1.9×  |

## Not in this patch

Recorded in `dev/ROADMAP.md` for 1.1, because each adds API or changes output:

- A stream-safe option (UAX #15 D4: insert U+034F so no more than 30 non-starters appear in a row). Not the default: it changes output.
- A `Cow`-returning normalization entry point, so already-normalized input is not copied.
- Normalizing without the `Vec<char>` scratch buffers, and trie tables in place of range tables (internal, no output change, but a rewrite).
- Width corrections for Hangul Jamo Extended-B (zero width) and visible format characters such as U+0600–U+0605 (one column). These change `char_width` for assigned code points.

## Verification

Run on Windows x86_64, Rust stable and 1.85:

```bash
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo clippy --all-targets --all-features -- -D warnings
cargo clippy --all-targets --no-default-features -- -D warnings
cargo +1.85 clippy --all-targets --all-features -- -D warnings
RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --all-features
cargo test --all-features
cargo test --no-default-features
cargo +1.85 test --all-features
cargo bench --no-run
```

All green, with `dev/ucd/` fetched by `dev/fetch_ucd.sh` and `UNICODE_LANG_REQUIRE_UCD=1`. Counts:

- `--all-features`: 39 unit + 12 property + 5 adversarial + 2 conformance + 9 doctests.
- `--no-default-features`: 17 unit + 6 property + 6 doctests (normalization tests are gated on `alloc`).
- The full `NormalizationTest.txt` suite: 19 965 records plus whole-codespace identity, all four forms.
